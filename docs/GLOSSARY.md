# Glossary

Terms used across DocSage's documentation: plain English first, precisely
second. Product terms come first; engineering terms follow.

| Term | In plain English | Precisely |
|---|---|---|
| RAG | Before answering, the app first searches your own documents for the relevant passages, so the answer is grounded in your policies and can point to the exact page it used. | Retrieval-augmented generation: retrieval (a cosine search over embedded chunks) selects passages, and a model (or the demo extractor) composes the answer from them; every answer carries a citations array (document, page, snippet, score). |
| Agentic ingestion | At upload, a series of AI passes reads the document ahead of time: a summary, keywords, the questions it expects users to ask, captions for images, and preambles for tables. Every later question gets faster and better aimed. | The enrichment stage of the ingestion pipeline ([ADR 0004](adr/0004-agentic-enrichment-at-ingestion.md)): model passes produce artifacts persisted as `enrichments` rows, caption chunks, and table preambles, so question time stays a single indexed vector search and model cost is paid once per document. |
| Embedding / vector search | A numeric fingerprint of a passage's meaning, so things worded differently but meaning the same land near each other; the search finds the passages closest in meaning to the question. | 1536-dimension normalized vectors stored in pgvector (one `vector(1536)` column, one HNSW cosine index); retrieval takes the top 6 nearest neighbors by cosine distance per provider ([ADR 0002](adr/0002-uniform-1536-dim-pgvector.md)). |
| SME (subject matter expert) | A reviewer trusted for one specific topic (budget, security, workplace policy). Nothing goes agency-wide until an SME for that topic approves it. | A per-topic relationship in `sme_designations`, not a role; a topic's library documents wait in `pending_sme` until a designated SME (or an admin) decides; decisions are append-only audit rows; the uploader can never approve their own upload ([ADR 0005](adr/0005-access-model-and-sme-approval.md)). |
| Citation / provenance | Every answer shows where it came from: the document, and the page when the source has pages, as chips the reader can check. | A `citations` event on the SSE stream carrying chunk id, document title, snippet, cosine score, and optional page; the answer's `[n]` markers must match the array order. |
| Demo mode | The whole product runs with no API keys: answers are assembled from top passages, and the screen says "Demo mode", so nobody mistakes them for model output. | A third provider, `demo`: SHA-256-seeded xorshift64star PRNG vectors (1536 dims, implemented byte-identically in Python and C#), deterministic extractive stand-ins for enrichment, and a `demo_mode` flag reported by `/api/health` ([ADR 0006](adr/0006-offline-demo-mode.md)). |
| Personal vs agency library scope | Your own uploads stay private to you; the agency library is the curated policy set, and nobody sees a library document until an SME approves it. | `documents.scope`: `personal` documents are visible only to their owner (plus the labeled admin chat scope); `library` documents become visible to everyone once `approved`, and before that only to admins and the topic's SMEs. |
| Dual backend | The same API is deliberately built twice, once in Python and once in C#, against one shared database; if the same tests pass on both, the contract is real. | A FastAPI reference implementation plus an ASP.NET Core parity slice ([ADR 0001](adr/0001-dual-backend-strategy.md)); [CONTRACT.md](CONTRACT.md) is the single source of truth, alembic owns the schema, and the .NET side never migrates. |
| SSE (Server-Sent Events) | The server streams the answer to the browser word by word as it is written, instead of making the user wait for a finished paragraph. | A stream on `POST /api/chat/sessions/{id}/messages` with event types `delta`, `citations`, and `done`; errors mid-stream arrive as events because the HTTP status has already been sent. |
| HNSW / cosine similarity | The index that keeps "closest meaning wins" search fast as the corpus grows, and the score that says how close two meanings are. | pgvector HNSW index (`vector_cosine_ops`) with cosine distance; `hnsw.ef_search` stays at the pgvector default; real providers apply a 0.15 similarity floor, demo retrieval is rank-only. |
| Provider-qualified space | Vectors from different AI providers are like coordinates from different maps: same size, incompatible. Every query is measured against each map it is actually on. | `documents.embedding_provider` and `embedding_model` are recorded per document and immutable; the query is embedded once per provider present in the candidate set (at most two), and per-provider results merge by score before the top-k cut ([ADR 0003](adr/0003-provider-qualified-vector-spaces.md)). |
| Parity testing | Run the same user-journey tests against both builds of the app; a test that passes on one and fails on the other is a parity bug. | One Playwright suite driven by `E2E_BACKEND=fastapi\|dotnet` (36 tests per backend) runs unchanged against both servers; parity bugs it has caught: registration not setting the session cookie, and `embedding_model` missing from the summary DTO ([e2e/README.md](../e2e/README.md)). |
| FastAPI / ASP.NET Core parity pair | Two mainstream server frameworks (Python's and Microsoft's); DocSage implements the API in both to keep the contract honest. | `backend/` (FastAPI, SQLAlchemy 2, alembic schema owner) and `dotnet/` (minimal APIs, Npgsql + Dapper), sharing argon2id hashes, one sessions table, and byte-identical demo vectors. |
| argon2id / PHC string | An industrial-strength way of turning passwords into irreversible codes, written in a standard format both languages can read, so either backend can verify any login. | Argon2id password hashes in PHC string format (`$argon2id$v=19$m=...$salt$hash`): Python via argon2-cffi, .NET via Isopoh; no proprietary encodings on either side ([ADR 0007](adr/0007-cross-runtime-auth-interop.md)). |
| 1536-dim truncation | A shorter cut of a larger vector from the same family that still preserves the meaning order; both providers agree on the exact size, so one index fits everything. | 1536 dimensions requested per provider at embed time (Matryoshka truncation: Gemini `output_dimensionality`, OpenAI `dimensions`); 1536 is `text-embedding-3-small`'s native size and stays under pgvector's 2,000-dim HNSW index limit ([ADR 0002](adr/0002-uniform-1536-dim-pgvector.md)). |
